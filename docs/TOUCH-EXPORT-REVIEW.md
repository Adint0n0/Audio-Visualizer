# 映像・音声の回帰検証

## 配信用ビルドでの確認

Linux 上の Chromium 156.0.8078.79、Three.js / WebGL 2、ANGLE SwiftShader を使用した。テストは Cloudflare Pages 用の `_headers` を適用して Vite の配信用ファイルを配信した。

- ネットワークをオフラインにしてエディタを再読み込みし、元の WAV の読取、320×180 の音声付き WebM（VP9/Opus）と MP4（H.264/AAC）を実際に書き出した。各 15 フレーム、映像 30 fps。AAC のエンコード末尾を含む MP4 は 0.512 s、WebM は 0.520 s。CSP 違反を検出せず、ページ・ワーカー間は cross-origin isolated だった。
- MP4 の可変フレーム間隔と音声開始オフセットがある素材で、約 0.25 秒→0.75 秒→0.25 秒とシークし、動画背景の赤→青→赤を読み取った。ダウンロードした WebM には元動画の音声と合成後の映像があり、独立した FFmpeg デコーダーで PCM RMS は 0.0863 だった。
- 更新中に破損した配信物を供給し、新バージョンのインストール失敗、古い 2 タブの継続利用、正しい次バージョンへの更新を確認した。キャッシュ破損時の再取得、オフラインでの復旧画面とオンライン復帰、25 MiB を越えるファイルのビルド拒否も確認した。
- Firefox ESR 153.5.1 と Mesa でも最新の初期シーンを実際に書き出した。ブラウザの別の動画要素で読み取った MP4 は 1920×1080、0.255958 秒、132,948 バイト。配信サーバーを止めてから再読み込みし、エディタと WAV が復元されることを確認した。
- 第 3 のエンジンとして WebKitGTK MiniBrowser 2.52.6 を起動した。元のネイティブ AAC 経路では 24 kHz 素材の音声が 61.333 ms 遅延した。試験パケットの開始時刻を検査し、該当構成では同梱の WASM AAC に切り替えて再試験するよう改善した。修正後の 320×180 MP4 は映像・音声とも開始 0 秒。映像は 0.25 s / 8 フレーム、AAC は 0.256 s。HTTP サーバーの停止後も再起動および同梱 WAV の読取が成功した。WebKitGTK の結果で iPhone や macOS Safari の性能は評価できない。

## デモと計測方法

`node scripts/render-showcase.mjs` は実際のエディタでテンプレートを切り替え、同梱の Phase Drift.wav の 2–10 秒を 4 つの連続する 2 秒区間として書き出す。各ファイルが 1280×720、30 fps、60 フレーム、H.264/AAC であることを ffprobe で検査する。デモでは 4 本の映像トラックを再圧縮せず連結し、元楽曲の連続した同一区間を一度 AAC 化した。各区間に別々のコーデック・プリミングが入らないようにするためである。配布用デモはリポジトリの docs に置き、PWA の初回キャッシュには含めない。

プレビュー計測は、このクラウドの Chromium とソフトウェア描画で行った。1440×960 のブラウザで音声を再生し、WebGL に実際の draw 呼び出しを送ったアニメーションフレームの時刻を収集した。計測区間は 2.5 秒以上、4 個以上の描画フレームまで。p95 は連続する描画の間隔、書き出し時間はボタンを押してからダウンロード可能になるまでの実時間である。複数の統合テストが同じ CPU を使用しており、実機 GPU の FPS・電力・熱特性は未測定。

`node scripts/render-showcase.mjs --measure` で各シーンの再生後に 1.8 秒のウォームアップを設けて計測した。自動解像度調整を有効にし、表の順に連続して切り替えた。解像度は各計測終了時のプレビュー描画バッファ。最後の列は同じシーンの 720p デモを 2 秒ずつ書き出した別の実行の結果である。

| シーン | プレビュー解像度 | 描画回数 | 描画 fps | 描画間隔 p95 | 720p・60 フレームの書き出し |
| --- | --- | ---: | ---: | ---: | ---: |
| Binary Stars | 849×478 | 5 | 3.58 | 467 ms | 51.3 秒 |
| Halo Index | 743×418 | 13 | 4.09 | 817 ms | 36.2 秒 |
| Level Meter | 637×359 | 8 | 3.93 | 533 ms | 72.2 秒 |
| Liquid Pearl | 425×239 | 12 | 4.65 | 483 ms | 88.6 秒 |

このソフトウェア GPU 環境では、自動解像度調整後も 30 fps には届かなかった。書き出し時は全シーンで 60 フレームを生成した。Binary Stars の同一区間をプレビュー倍率 1× と 0.5× で書き出し、冒頭 3 フレームを同じ 96×54 RGB にデコードすると、画素値の RMS 差は 0.077 / 255 だった。

デモは 8.000 秒、12,044,552 バイト、1280×720・30 fps。映像 H.264 と音声 AAC の開始はともに 0 秒で、全 240 フレームの表示時刻をフレーム番号 / 30 と比較した最大誤差は 0.34 マイクロ秒未満だった。[4 シーンのデモ動画](touch-studio-demo.mp4)

## 高解像度・長尺の書き出し

- 配信用ビルドをオフラインで再起動し、初期シーン Binary Stars と同梱 WAV の 2.00–2.25 秒を VP9/Opus に書き出した。3840×2160、60 fps、15 フレーム。独立したデコーダーで画像を読み取り、コンテナ長 0.260 秒を確認した。エンコーダー試験と検証を含む実時間は 34.275 秒だった。
- タイミングを既知にした合成テストで、1920×1080・24 fps・60 秒の VP9/Opus は全 1,440 フレームをデコードした。1920×1080・1 fps・1,799.5 秒の H.264/AAC では 1,800 フレームとパケットコピーした音声を確認した。開始後 1、900、1,798 秒で音声クリックのピークと白フレームの差はいずれも +8.44 ms だった。分数フレームレート 30000/1001 fps でも各フレームの時刻を確認した。
