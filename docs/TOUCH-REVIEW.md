# タッチ編集と画面サイズの検証

公開版の基準には `origin/main` のコミット `7906b2bc0113b3b24866af99025b41b8be99c940` を使用した。独立したディレクトリに展開してビルドし、改修版も別のディレクトリでビルドした。どちらも Cloudflare Pages の `_headers` を適用するローカル配信で確認した。検証環境は Linux、Chromium 156.0.8078.79、WebGL 2 / SwiftShader、DPR 1。

[改修前の全画面一覧](review/touch/before/matrix.jpg) · [改修後の全画面一覧](review/touch/after/matrix.jpg) · [個別の原寸画像と計測値](review/touch/after/)

## 修正前に再現した問題

- 360×640 でキャンバスの左端は 8 px、幅は 366 px あり、右端の 14 px が表示領域からはみ出した。ドキュメントの `scrollWidth` は 360 px のため、ページ幅だけを確認する従来の検査は合格した。
- 同じ画面で Inspector を開くとキャンバスが 0×0 になった。Advanced に切り替え、指を (340,400) から (340,190) へ動かしても、1,361 px のスクロール余地がある設定欄の `scrollTop` は 0 のままだった。表示領域の左端は −8 px、幅は 382 px だった。[指を離した直後の画面](review/touch/before/inspector-after-swipe.jpg) · [修正前の測定記録](review/touch/before/interaction.json)
- キャンバスで同時に2本の指を押して拡大しても、保存されたシーンの変形値はすべて同じだった。イベントログで両方の `pointerdown` と `pointerup` がキャンバスに届いたことを確認した。

## 操作の検証

Chromium DevTools Protocol の `Input.dispatchTouchEvent` で指ごとに ID を保持したまま接触、継続、部分解放、キャンセルを送った。ページが受け取った PointerEvent の `isTrusted` を確認し、確定後の変形は IndexedDB の実際の自動保存から読み取った。24 レイヤーのシーンを通常の JSON 読み込み機能で用意し、中央の球体を操作対象にした。

| 操作 | 結果 |
| --- | --- |
| 各パネルの縦スワイプ | ライブラリで 4,554 px、24 レイヤーで 1,318 px、基本の編集欄で 289 px の末尾まで到達した。各パネルのスクロール所有者は `dock-scroll` で、ドキュメントの位置は 0、プレビューは常時表示された。 |
| 空白をタップ → 球体をタップ → 長押し | 選択枠の消去、再表示、名前付き操作メニューの表示を確認した。初回レビューで、指を離しただけでメニュー内の別操作を誤発動する問題を発見した。修正後は長押し解放時にメニューを開き、次のタップまで表示を維持した。 |
| 1本指移動 → 2本指のピンチ＋ひねり → 1本指で続行 | 位置 (1.476, 0.871, 0)、Z 回転 −30°、XYZ 倍率 2。接触数を戻した際に大きさが跳ねず、プレビュー上部の Undo を1回タップすると操作前の全成分に戻った。 |
| スナップ | 中央から 7 px 移動するとガイドが現れ、12 px まで移動しても保持した。キャンセルでガイドが消えた。 |
| 割り込み | 2本指操作の `touchCancel`、DOM の実際の `releasePointerCapture`、接触中の向き変更で未確定の変形を破棄した。 |
| 3D回転 | 1本指の弧状操作で XYZ が約 (−16.86°, 23.51°, 3.53°) となり、位置は維持された。 |
| 編集ビュー | 1本指・2本指で編集ビューを変更すると描画ピクセルが変化し、プロジェクト内の出力カメラと物体の変形は元の値を維持した。 |
| 画面端 | Chromium の safe-area を上 20 px・下 28 px に設定すると、上部バーと下部ナビの実際の退避量もそれぞれ 20 px・28 px になった。 |
| 数値入力と再生中の変更 | 精密変形欄で 360×390 へのビューポート縮小後も X に 1.25 を入力して確定できた。再生中にキャンバスをドラッグすると再生時刻が進んだまま移動が保存された。 |

## 再実行と実機の範囲

```sh
npm ci
npm run build
node scripts/check-touch.mjs
node scripts/check-studio.mjs
```

`FORMANT_TEST_DIST` でビルド出力、`FORMANT_TOUCH_ARTIFACTS` で画像と JSON の出力先を指定できる。既定では一時ディレクトリに書き出す。`--baseline` は旧 UI の再現記録用。

デスクトップでは `check-studio` で再生、シーク、範囲、Undo/Redo、日英切り替え、出力設定の復元、完全プロジェクトのダウンロードも再確認した。タッチイベントはブラウザ入力経路を通して送った。物理的なスマートフォン・タブレットの GPU、OS ネイティブのキーボード、実際の振動、ブラウザのアドレスバーの出入りは未検証。キーボード欄の結果は開閉に伴う表示領域の変化を模擬したもの。

## 初見操作を想定した評価

評価者は実装・テスト担当エージェント。人を対象にしたユーザビリティ試験は実施していない。新規プロジェクトの流れを、シーンの探索と適用、レイヤー選択、プレビュー内の変形、吸着確認、色・形状・音声設定、レイヤー追加、再生、保存・書き出しの順に確認した。入力と出力の検査は `check-studio`、`check-composite`、`check-offline` と併用した。

変形時に軸の細いハンドルへ触れる工程をなくし、選択済みなら表示領域内のドラッグで移動できる。回転と拡縮には2本指を使える一方、上下の手順を覚えずに精密変形の軸ボタンへ切り替えられる。誤操作の復旧には、複合操作を単位とする Undo と、確定前に中断した場合の復元を用意した。テンプレートはプレビューしてから追加か置換を決められる。探す際はカテゴリーと描画負荷を使える。

残る操作上の制約は、短い横画面で16:9のキャンバスを出力比率どおり表示すると細部が小さくなることと、長押しや3D回転には初めて使う際に発見が必要なこと。集中モードとレイヤー一覧からの選択を確認し、通常モードには短い操作のヒントを表示する。工程の達成率や作業時間は人による試験で測定していない。
